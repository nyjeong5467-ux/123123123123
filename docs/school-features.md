# 학교 특징 → 종사자 안전보건점검표 자동 '해당없음' [174]

학교 상세 › **학교 특징** 칸의 [편집] → 있음/없음 → [저장]. 저장하면 12개 항목이 모두 확정 저장되고, 이때부터 점검표에 자동 적용된다.

- 저장: `PUT /schools/{sid}/features` `{ "features": { "대형 곰솥": true, "엘리베이터": false, … } }` (키 = 화면의 특징 이름 그대로)
- 조회: `GET /schools/{sid}/features`
- **저장된 특징이 없으면(빈 맵) 자동 해당없음을 적용하지 않는다** — 화면에 "아직 저장되지 않았습니다" 안내.

## 규칙표 (웹 `src/pages/InspectionForm.tsx` EXCL_RULES 와 동일)

| 특징 키 | 값이 '없음'(false)이면 | 자동 해당없음 항목 | 사유 문구 |
|---|---|---|---|
| 엘리베이터 | 없음 | 시설 5, 시설 6 | 엘리베이터 없음 |
| 대형 곰솥 | 없음 | 급식 32 | 대형 국솥 없음 |
| 계단 (2층 이상) | 없음 | 급식 5 | 계단 없음 |
| 덤웨이터 | 없음 | 급식 13 | 덤웨이터 없음 |
| LPG 사용 | 없음 | 급식 22, 급식 23 | LPG 미사용 |
| 충돌방지용 거울 | 없음 | 미화 3 | 충돌방지용 거울 없음 |
| 미화 고소작업 | 없음 | 미화 7 | 미화 고소작업 없음 |
| (특징 아님) 미화 종사원 0명 | 대장 종사자 인원 | 미화 3, 미화 7 | 미화 종사원 없음 |

- 항목 번호 = 공정별 점검표 문항 순번(코드 `급식-32` 형식).
- 아직 항목과 연결되지 않은 특징: 가스 튀김기 · 스팀 오븐 · 지하 기계실 · 옥상 출입 · 별도 당직실 (화면 저장만, 자동 해당없음 없음).
- 값 판정: `true`·`1`·`"1"`·`"yes"`·`"있음"` = 있음, 그 외 = 없음.

## 현장 앱(APK) 담당자 참고

- 앱 점검표도 같은 `GET /schools/{sid}/features` 를 읽어 위 규칙표대로 해당 문항을 '해당없음'으로 미리 선택(비고에 사유)하면 웹과 결과가 같아진다.
- 규칙을 한 곳에서 관리하려면 서버가 규칙표를 내려주거나(예: org 문서 `inspection-excl-rules`), 앱·웹이 이 표를 똑같이 갖고 있어야 한다.

## 학교 상세 화면 편집 방식 변경

- 맨 위 전체 [편집] 버튼 제거 → 칸마다 [편집]: 학교 정보(편집 안에 [학교 삭제]) · 현업종사자(명단 없을 때) · 학교 특징 · 특이사항 · 확인자 · 점검자 이력.
- MSDS · 산재 현황 · 월별 진행 이력은 [＋ 추가] 버튼을 항상 표시.
- 편집 중인 칸에 저장하지 않은 변경이 있는데 다른 칸 [편집]을 누르면 확인창.
